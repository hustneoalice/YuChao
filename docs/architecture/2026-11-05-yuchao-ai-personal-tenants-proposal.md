# 驭潮AI赋能与个人付费多租户：实现途径建议

日期：2026-11-05。状态：分析建议，未实施。用户已明确主要客户是个人付费用户；微信服务外部客户，在个人微信侧使用。

## 产品定位与方案选择

建议在现有FastAPI、行情、指标、图表和筛选基础上增加AI工具层、个人机器人任务和消息渠道。模型理解与解释；系统计算、筛选、持久化任务、生成坐标、判定触发和投递。

可选路径：
1. 现有驭潮内建工具调用服务（推荐）：直接复用权限/行情/指标，支持图表动作和准确解释，需建设任务与模型治理。
2. 外接通用低代码AI平台：适合快速做文档问答/报告草稿，但实时指标、盯盘、用户隔离仍需驭潮提供API，不会消除核心工作；凭据、上下文和计费容易分裂。
3. 另造完整智能体平台：成本和维护面过大；本阶段不建议开放任意代码、任意工具安装或自由无限循环。

第一版每个用户一个个人空间，以数据库tenant_id标识。暂不建设团队、邀请、成员管理；保留tenant与user概念分离，便于后续演进，但不预先实现未请求的团队功能。

## 当前源码核验的基础与缺口

- `app/auth/store.py`：SQLite用户态库；users、watchlists、prefs等按user_id保存；未见完整tenant模型。行情DuckDB与用户态已分库。
- `app/integrations.py`及`app/routers/v1/me.py`：已有按用户的模型provider/base_url/model/key配置及连通测试，不能等同于已有生产AI问答/工具编排。
- 飞书已有Webhook推送、核心标与两点乾坤定时任务：可复用消息格式及用户投递设置，尚不等同于应用机器人的双向消息、菜单与卡片回调。
- `app/updater/collectors/targets.py`：已有后台指标预计算，适合向AI暴露只读筛选工具；重计算不能放进聊天请求，更不能让模型阻塞DuckDB写入任务。
- 图表已有指标注册与自定义绘制，但自然语言到图表的受控指令桥及租户级画线保存尚需建设。
- `kline.ts`短线强势实际用C>=MA10，后端compute_target_scan里short_orange仍用C>MA10；AI接入前要统一边界。
- 钱袋子money_indexes在后续反弹6%确认后，将标记放到ext+1的历史K线上。筛选/盯盘必须保存确认时刻，不能以图上日期冒充当时已知。历史图形与真实可交易事件应分开。
- 现有配置设计允许SQLite明文保存模型key与Webhook凭据；面向付费多租户需加密、服务端使用、脱敏回显与日志保护。

以上为本地当前checkout源码核验，未对本轮AI能力进行云端运行验证。

## 六类需求的实现

### 1. 智能问答

统一会话入口，结合当前股票、周期、复权、可见图表、用户自选及明确授权的数据范围。用工具查询行情、资金、板块、指标和历史筛选；知识检索覆盖软件说明、指标定义与用户文档。用户私有文档、聊天和持仓不进入共享检索空间。

实时行情问题调用数据工具，文档问题检索知识库；每条金融事实尽量带数据时点、来源及相关数值。查询失败要返回可见失败状态，模型不能用猜测填补。模型网关支持文本模型与视觉模型的能力路由，配置统一，避免把产品绑在单一厂商；具体厂商与费用另做同题评测后选定。

### 2. 识图、画线与自然语言指标开关

驭潮自己的图表优先传结构化上下文：股票/周期/复权、K线、指标数值、坐标轴与现有画线。截图作为辅助解释证据，避免从像素猜本来可查询的精确数值。

外部截图使用视觉模型识别证券、周期、时间、指标及候选形态，输出可编辑识别结果；信息不明确时请求补充，不能直接落精确价位。确认标的和周期后重新查询数据并重新定位。

模型输出受schema约束的动作：开启/关闭指标、切换周期、增加水平线/趋势线/区间、撤销动作。服务端校验指标权限和坐标；图表按时间和价格渲染，不保存屏幕像素作为业务坐标。AI画线标明依据、锚点和生成时间，可以编辑/撤销并按租户云同步。

### 3. 用户机器人：对话、筛选、盯盘

机器人是受控配置：名称、用途、股票池、指标组合、频率、通知渠道及额度。用户通过自然语言配置，系统先展示可读规则卡，确认后成为持续任务；修改对话生成规则差异。即时只读查询可直接执行，不必层层确认。

自然语言编译为类型化规则树，支持AND/OR、最近N个交易日、持续N根、上穿/下穿、幅度、排名和排序，不允许模型直接生成并执行SQL/Python。

定时器持续盯盘，模型无需不断运行。行情变更先计算共享特征，规则引擎找事件，只对命中项调用AI生成解释，明显降低费用。事件用状态机标识初次命中/持续/撤销/再次命中，配冷却和收盘确认，避免每轮重复推送。

频率由行情源真实刷新率、订阅范围和套餐决定；第一版以自选/筛选结果池的分钟级为目标，不能仅靠现有日线/快照承诺逐笔实时。全市场同指标批量算一次，多个用户复用数据，不为每个机器人重复拉全市场。

### 4. AI复盘、盘前报、盘后报

先生成确定性数据包，再让模型写报告。公共部分：指数、板块、资金、涨停与主力军情；个人部分：自选、机器人命中、关注主题与变化。使用真实交易日历和Asia/Shanghai，分别标记交易日期、数据截止与生成时间。

盘前报主要引用上一交易日收盘与截至生成时可用的信息；盘后报等待行情/资金任务的完成水位，不能只看固定时钟。数据未齐时标注缺项、延迟重试，不能把旧资金日期伪装当天。晚间最终版与盘中临时版分别留版本，按日期可查询重生成并看到变化。

公共事实包共享缓存，个性化总结按租户生成；同一数据版本与同一报告配置不重复收费生成。

### 5. 全部指标进入选股工具

建设统一指标注册表：indicator_id、中文别名、参数、输入、支持周期、最小历史长度、输出值/事件、公式版本、来源/验证程度、是否重绘、数据支持状态、成本。钱袋子、趋势柱线、MACD、短中线趋势以及其他指标逐个登记，未支持筛选的指标在界面明确显示“仅绘图/待接入”。

共享算法规范及跨语言一致性用例，保证浏览器显示、后端扫描、机器人和报告用同一口径。可以先保留TS绘图和Python计算，前提是建立同输入逐点校验；不必为了复用强行把所有实现迁到一种语言。

值指标、事件、图形对象分开：趋势柱线是值/过零事件；钱袋子是确认事件；眼睛/保护线/箭头是规则衍生图形。选股按事件查，不靠视觉模型看几千张截图。复刻/近似/约定规则保留来源标签，AI不得改称众赢原公式。

每条事件保存：标记日、首次可确认时刻、当前状态、计算版本、价格复权和数据时点。历史回放只能使用当时可知的数据；此项尤其适用于钱袋子/转折类回标。

### 6. 飞书与微信

飞书：现有Webhook适合单向群推送；双向对话、菜单、卡片按钮应接应用机器人。菜单建议：今日候选、我的机器人、盘前报、盘后复盘、订阅设置。卡片按钮：查看K线、解释命中、加入自选、启动/暂停盯盘。按钮事件进入同一权限与规则服务。

官方文档已核验：自定义Webhook机器人卡片支持URL跳转，但不支持服务端回调交互；应用机器人具有菜单能力。个人付费用户跨飞书组织使用时，需要选择面向客户可安装的应用分发方式及平台审核；不能默认一个企业自建应用可供所有外部个人使用。可先在受控测试组织验证，再走商业分发。

微信：用户明确面向外部客户个人微信，推荐官方服务号入口＋驭潮H5会话/配置/报告页。菜单提供问答、选股、我的机器人；公众号消息回调作为交互入口，长任务返回状态/结果链接，H5承接流式对话与复杂图表。通知根据服务号实际主体、权限、可用模板/订阅能力和用户授权设计。微信客服可以作为候选互动通道，发送窗口和主动消息能力须按实际账号最新规则核验。

本轮微信官方具体API页面工具读取失败，因此不承诺确切消息条数、时间窗口、金融内容模板资质或任意日报模板可获准。渠道PoC要先用真实主体账号跑通：外部微信用户绑定→发问→收到回复→订阅→实际可发送的提醒。若某类主动提醒不获准，提供公众号入口内查看/H5订阅结果，飞书承接需要高频触达的任务。不能把个人微信号的窗口接管或非官方群机器人作为SaaS默认依赖。

渠道用户须通过一次性绑定流程关联驭潮账户。服务端使用经过验证的open_id/union映射等身份绑定记录，不能信任用户在消息中输入的tenant_id。飞书组织ID不等于驭潮个人租户ID：同组织多人仍各自付费隔离。

## 技术结构

浏览器/H5/飞书/微信 → 统一会话与身份入口 → AI编排服务 → 白名单工具 → 行情/指标/筛选/图表动作/机器人/报告。

应用状态建议PostgreSQL；共享行情继续DuckDB/现有数据服务，只由已有writer负责市场数据写入。Redis提供热点缓存、任务队列与限流；独立worker执行AI/报告/消息任务，不能把模型网络等待放到行情写入流程。可采用Celery+Redis作为明确的初始实现；业务job状态、额度账本与投递记录落PostgreSQL，不把Redis当唯一持久账本。

第一版建议以LangGraph承载单智能体的受控工具调用、研究状态、流式结果和中途恢复；常规盯盘/定时报送仍由独立调度与任务账本执行。不引入自由多智能体协商、向量库集群或另造复杂工作流平台。知识库规模小可在PostgreSQL使用向量扩展，且检索强制带租户边界。

## 多租户、付费与可靠性

基础表建议：tenants（个人空间）、users（登录身份）、conversations/messages、agents、agent_rules、jobs/runs、reports、chart_annotations、channel_bindings、delivery_outbox、usage_ledger、audit_events。个人租户先一人，不做团队成员表与权限界面。

所有私有对象强制tenant_id；查询写入由认证上下文注入，客户端不能指定任意租户。数据库行级隔离与服务层检查双层验证，运行时连接不能使用绕过RLS的管理角色。任务入队、worker取数、重试、SSE、缓存键、文件路径、向量检索及卡片回调都要保持同一租户上下文。

共享：市场原始数据、公共指标特征、公共事实包。私有：聊天、机器人/规则、自选、报告个性化部分、图表画线、渠道、凭据、用量与订单。共享缓存不能混入私人自选或历史对话。统一凭据加密，平台支付回调验签、重复处理幂等；套餐权限在服务端实时检查。

套餐应限制机器人数量、监控标的数、运行频率、模型/视觉额度、报告次数、历史保留期；扣费/额度先预留后结算，失败释放。到期停止新增耗费任务并保留只读历史，持续盯盘暂停并通知用户。

消息使用outbox、幂等键、重试和最终状态。渠道回调按事件ID去重，先快速响应再异步执行，防止平台重试触发重复筛选/推送。对每个用户设置发送频率与每日额度。

## 分期及验收

阶段一：指标与租户底座。统一强弱边界、确认时刻/重绘语义；个人空间与隔离；工具注册、共享特征、用量账本。验收：两用户互访私有对象失败；前后端同样本指标一致；历史回放不提前出现确认信号。

阶段二：最小可演示闭环。智能问答＋自然语言筛选＋开启指标＋可撤销画线；将一次筛选保存为机器人，后台运行，飞书卡片可查看原因。微信服务号/H5同时做真实渠道PoC，尽早识别账号能力限制，不把微信验证拖到最后。

阶段三：个人机器人与报告。多策略保存、命中/撤销/冷却、日期查询、盘前/盘后水位、用户偏好、套餐额度。验收：同一事件不重复轰炸、过期数据可见、失败可重试、到期任务暂停。

阶段四：识图增强与正式渠道分发。外部截图识别、锚点编辑、跨设备同步；完成飞书商业分发/微信所需账号权限与上线审核。验收：截图低置信时不能自动编造精确线位；渠道绑定与回调跨租户隔离。

建议第一个演示场景：用户说“从我的自选中找近3个交易日趋势柱线上穿零轴、目前仍在零轴上、短线强势的股票，排除ST，开日K和MACD；保存机器人，盘中首次命中推飞书，收盘总结原因”。系统展示解析规则与数据时点；用户确认保存后运行；卡片查看命中证据和图表。钱袋子待确认时刻机制完成后进入同等闭环。

## 进一步明确：联网研究也在首期架构内，采用轻量智能体框架

此前对单次任务解析的说明“不需要完整智能体框架”仅适用于窄范围任务创建，不能覆盖用户已提出的泛化研究需求。用户进一步明确主营业务、资金、盈利、季报及联网搜索，因此建议选用Python LangGraph作为智能体编排层；由单个智能体按问题动态调用受控工具，复杂研究使用可恢复的多步流程。不是只做固定意图分类器，也不以多个自由对话的智能体作为起点。

官方核验：LangGraph提供有状态编排与持久化能力，官方PostgreSQL checkpointer可保存运行检查点；LangChain可提供工具调用、结构化输出与中间件，但不是使用LangGraph的必要依赖。框架不提供驭潮行情、指标公式、业务权限、订阅任务和租户计费，需要独立实现。持久化检查点中的工具副作用仍须业务幂等，不能以框架可恢复推断创建/推送恰好一次。

典型问题“阳光电源主营做什么，近期资金怎样，最新季报盈利质量如何”：
1. 解析证券与用户问题，决定研究维度及截至时点。
2. 内部工具读取公司资料、资金序列、财务数据和用户所指周期。
3. 外部搜索查询最新公告、正式定期报告与必要的公开新闻；优先公司、交易所及正式公告来源。
4. 网页读取和PDF提取正文、表格、页码。搜索摘要仅用于发现来源，不直接当季报结论。
5. 程序统一报告期/发布日期、单季/累计/TTM、合并范围与单位，计算同比、利润率、扣非、现金流等。
6. 检查缺项和来源冲突，只补查需要的信息，输出带来源和数据时点的回答；证据不足明确缺项。
7. 用户说“以后每次出季报都这样分析”时，调用独立任务服务创建公告监测订阅。

工具层建议：resolve_symbol、get_company_profile、get_fund_flows、get_financials、list_announcements、search_web、read_webpage、extract_report_tables、calculate_metrics，及原先图表/指标/筛选/任务工具。工具能力目录可扩展，模型可以组合调用，不要求提前写死每种问法。新增市场数据能力仍应作为后端工具接入，不让模型临时写脚本操作生产数据库。

费用与性能：主营问答通常一两次数据工具即可；复杂季报研究异步执行并流式返回进度，设置工具次数/时长/搜索预算。公告原文解析与公共财务事实跨用户共享缓存，个人研究偏好与对话隔离。联网网页和PDF视作不可信资料，不能覆盖系统指令、触发未授权发送或读取其他租户数据。

执行职责继续分开：智能体理解/研究/解释/生成任务草稿；指标规则引擎负责数值与事件；任务系统负责持久订阅、交易日、到期、调度和幂等投递；模型网关和账户系统负责能力、额度和权限。无需让LangGraph持续挂着一个运行数周的价格盯盘循环。

此为技术建议更新，尚未安装框架、调用实际付费模型、为用户创建订阅或部署AI服务。

## 配置平台需求后的选型更新

用户进一步明确需要现成的智能体配置、工具配置界面。因此不再将裸LangGraph作为首选实施路线，先对Langflow与Coze Studio作同题PoC；接受适当商业授权时比较Dify。平台已有执行引擎就不再额外叠加一套LangGraph。具体许可、社区版边界、维护状态与试验标准见同目录`2026-11-05-yuchao-ai-platform-comparison.md`。仍未安装/部署任何候选。
