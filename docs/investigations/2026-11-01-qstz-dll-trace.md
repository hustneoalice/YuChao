# 强势调整 DLL 追踪

## 身份与边界

`Qiangshitiaozheng.dll` 46856字节，PE32 x86，SHA256 `657b225605a817592c9db4dd1a79ba4f7b99b02be43df9399dc1a3f7e6ec5564`。系统配置band1绑定此文件。REA完整导出表仅一个RegisterThrdFunc，入口0x10001230；返回注册表0x10008018，仅ID1 -> 0x10001010。

CONFIG/sys_index.xml内实际发现的SYS_DLL1调用者为“强调買賣”：

```
bs:=SYS_DLL1(1,H,O,L,C,V);
DRAWICON(bs>0 AND bs<100,L,1);
DRAWICON(bs>=100,H,2);
```

所以该DLL确实被买卖图标指标使用；尚未建立它与独立“强势调整”眼睛/连线/保护位的直接调用关系。不能以文件名当作该独立指标算法已找到的证明。涨停战法内部同名条件仍不是目标。

## 控制流与部分已还原条件

- 0x10001010创建局部计算对象（448字节），依次运行构造/输入绑定0x100013b0、形态处理0x10001940、信号处理0x10003ff0，再复制输出并销毁对象。
- 参数ABI与缠论同为cdecl：长度、输出、H、O、L、C、V。对象+0x30输出指针，+0x34 H，+0x38 O，+0x3c L，+0x40 C，+0x44 V，+0x48长度。
- 第一阶段涉及H/L/C比较和多个形态状态，存在1–43状态分派（0x10001bb9的switch），不是单条量比条件。各状态含义未全部恢复。
- 第二阶段包含成交量120递推平滑和收盘价60递推平滑。超过初始化区后为 `(119*prev+V)/120` 和 `(59*prev+C)/60`，不能写成普通MA120/MA60。
- 0x100042eb..0x10004316检测 `H==C && float32(C/prevC)>=1.095`。这里涨幅边界是>=；不能照搬此前用户候选中的严格>。
- 检测后保存涨停日L到对象+0x78，另保存min(当日L,前日L)到+0x80，开始跟踪计数和后续最高价。
- 0x10004527..0x10004580有 `C<0.98*保存的低价基准` 且尚未持有标志时清空跟踪状态的分支；基准是+0x80的两日最低值，不能称为已经验证的眼睛保护位。
- 另有早期阶段H跨度>1.49倍的清空条件，以及最多15步等状态限制；全部条件尚未串成完整等价实现。
- 返回值0表示未绘图，(0,100)由公式画上图标，>=100画下图标。具体数字对应的全部形态分支尚未命名。

## 运行验证

在Windows独立32位PowerShell进程里调用原DLL，预加载sys目录中的VC++140依赖。使用yuchao本地前复权行情，用户已表示行情价格差异可忽略；这不消除样本范围或指标身份差异。

- 最近1000根，2022-08-26至2026-10-30：2024-11-27返回2，2024-12-13返回100，其余0。
- 完整可取得2031根，2018-05-25至2026-10-30：额外出现2018-08-07=2、2018-08-08=101、2019-06-03=4、2019-06-05=100；与1000根共同区间上述信号相同。
- 两组数据在2026年均无非零返回；2026-02-10/11/12以及2026-04-28全部0。

因此该DLL返回的买卖图标不能直接解释已知小眼睛截图，不能将此结果硬套回现有候选强势调整实现。仍需核对原软件“强调买卖”与“强势调整”两个入口，或找到独立指标的实际调用链。
